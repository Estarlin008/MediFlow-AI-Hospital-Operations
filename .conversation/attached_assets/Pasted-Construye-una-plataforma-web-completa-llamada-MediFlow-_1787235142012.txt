Construye una plataforma web completa llamada **MediFlow AI**, orientada a la gestión de emergencias y operaciones hospitalarias.

IMPORTANTE:

**NO implementar inteligencia artificial dentro de v0.**

La inteligencia, automatización, procesamiento de voz, extracción de información y lógica de priorización serán realizados externamente mediante **n8n**.

Por lo tanto, v0 debe encargarse exclusivamente de:

* Interfaz de usuario.
* Experiencia de usuario.
* Navegación.
* Visualización de información.
* Formularios.
* Dashboard.
* Gestión visual de pacientes.
* Historial clínico.
* Gestión de recursos hospitalarios.
* Simulación de datos.
* Simulación de respuestas provenientes de n8n.
* Preparación de la interfaz para conectarse posteriormente a APIs y webhooks reales.

No crear modelos de IA, chatbot médico, diagnóstico mediante IA, procesamiento de lenguaje dentro del frontend ni algoritmos inteligentes dentro de v0.

La arquitectura conceptual debe ser:

**Usuario**
→ **MediFlow Web**
→ **Webhook/API**
→ **n8n**
→ **Automatización**
→ **Resultado estructurado**
→ **MediFlow Web**

La plataforma debe parecer un sistema hospitalario real, completamente operativo, utilizando **datos ficticios**.

---

# 1. OBJETIVO DEL PRODUCTO

MediFlow debe centralizar el flujo hospitalario:

**Registro del paciente → procesamiento externo mediante n8n → priorización → cola de atención → consulta del historial → asignación de recursos → atención médica → alta/traslado → actualización del hospital.**

El valor principal que debe transmitir la interfaz es:

**registrar más rápido, priorizar mejor, encontrar la información del paciente rápidamente y conocer el estado del hospital en un solo lugar.**

El sistema debe estar diseñado para una demostración de alto nivel.

No crear una aplicación académica sencilla ni un dashboard genérico.

Debe sentirse como una plataforma **Healthcare Enterprise SaaS**.

# 34. OBJETIVO VISUAL FINAL

Cuando alguien abra MediFlow por primera vez debe poder entender inmediatamente:

### ¿Qué está pasando?

Estado de pacientes y emergencias.

### ¿Qué recursos tenemos?

Camas, personal, quirófanos, ambulancias, laboratorios y farmacia.

### ¿Qué hace MediFlow?

Centraliza el flujo y recibe automáticamente información procesada mediante n8n.

### ¿Cuál es el elemento diferencial?

**Registro por voz + automatización + priorización + historial clínico + visibilidad hospitalaria.**

La aplicación debe comunicar que MediFlow no reemplaza al personal sanitario.

Es una plataforma de **orquestación y automatización de operaciones hospitalarias** que ayuda al personal a trabajar más rápido y con información centralizada.

Construye todas las páginas, componentes, modales, navegación, datos simulados y flujos necesarios para que la plataforma pueda presentarse de extremo a extremo sin necesidad de un backend real.

Prioriza especialmente:

**1. Dashboard hospitalario**

**2. Registro por voz preparado para n8n**

**3. Cola y priorización**

**4. Historial completo del paciente**

**5. Recursos hospitalarios**

**6. Automatizaciones n8n**

**7. Flujo completo de atención**

La interfaz debe ser suficientemente completa para que, durante una presentación, el equipo pueda recorrer un caso de paciente desde su registro hasta su atención y observar cómo los cambios afectan al resto del hospital.
