Quiero que hagas una modificación importante del proyecto actual de MediFlow AI.

NO rehagas el proyecto desde cero.

NO cambies innecesariamente el diseño visual actual.

Quiero que mantengas la identidad visual y la estructura general de MediFlow AI, pero debes corregir un problema fundamental de UX y de concepto:

MediFlow AI no debe sentirse como un sistema hospitalario tradicional donde médicos y enfermeras tienen que llenar muchos formularios manualmente.

El objetivo de MediFlow es precisamente REDUCIR la cantidad de escritura y trabajo administrativo.

Por eso quiero transformar el flujo actual para que el REGISTRO POR VOZ sea una funcionalidad REAL y central de MediFlow.

La idea general debe ser:

PERSONAL HABLA
        ↓
MEDIFLOW CAPTURA LA VOZ
        ↓
TRANSCRIPCIÓN
        ↓
PROCESAMIENTO / ESTRUCTURACIÓN
        ↓
n8n
        ↓
DATOS ESTRUCTURADOS
        ↓
MEDIFLOW LOS PRESENTA
        ↓
PROFESIONAL REVISA
        ↓
CONFIRMA / CORRIGE
        ↓
SE GUARDA EL REGISTRO

El frontend debe prepararse para que n8n sea el motor de procesamiento y automatización.

NO crear un backend tradicional.

NO crear ASP.NET.

NO crear Express.

NO crear FastAPI.

NO crear otro servidor backend.

La integración debe quedar preparada:

REPLIT FRONTEND
        ↓
SERVICIOS / API CLIENT
        ↓

        ↓
PROCESAMIENTO Y AUTOMATIZACIÓN

==================================================
1. CAMBIO DE FILOSOFÍA DEL PRODUCTO
==================================================

MediFlow no debe obligar al personal sanitario a escribir manualmente toda la información.

La interfaz debe priorizar:

- Voz.
- Captura automática.
- Transcripción.
- Extracción de información.
- Estructuración automática.
- Revisión humana.
- Confirmación.

Los formularios manuales deben existir solamente como:

1. Fallback.
2. Corrección.
3. Edición.
4. Información que no pueda obtenerse mediante voz.

NO eliminar completamente la posibilidad de editar.

El médico o enfermera debe poder corregir cualquier dato generado automáticamente.

==================================================
2. ELIMINAR / REPLANTEAR "SINCRONIZAR"
==================================================

Actualmente existe un botón:

"Sincronizar"

Este botón no tiene un propósito claro dentro del flujo actual.

Si no existe una fuente externa real que deba sincronizarse, ELIMINARLO de la interfaz principal.

No quiero botones decorativos que aparenten realizar una acción que realmente no existe.

Revisar todas las apariciones del botón "Sincronizar".

Si existe una función técnicamente real detrás de él, documentar exactamente qué sincroniza.

Si solamente actualiza datos mock o recarga la pantalla, sustituirlo por:

"Actualizar"

si realmente corresponde a una actualización.

Pero NO utilizar "Sincronizar" para una simple recarga.

La terminología debe ser clara.

"Actualizar" = volver a consultar información.

"Sincronizar" = intercambiar/igualar información con una fuente externa.

No utilizar "Sincronizar" si no existe esa función.

6. Procesar la información.
